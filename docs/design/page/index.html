만다라트 · 디자인 개선 · 1차 시안

지금 디자인이 최선인지 확인했고, 세 가지 방향으로 다시 그렸어요

레퍼런스 조사 11갈래와 현재 화면 진단 8갈래를 마친 뒤, 같은 예시 데이터로 세 방향의 시안을 그렸어요. 아래에서 지금 화면과 나란히 비교해 보세요.

정해 주실 것은 하나예요. A, B, C 중 어느 방향으로 갈까요? "A로 가자"처럼 답해 주시면 그 방향으로 앱 전체를 고쳐요. "A에 B의 홈 화면"처럼 섞어도 돼요.

지금 디자인에서 확인된 문제

  • 주인공이 없어요. 모든 화면이 같은 바탕, 같은 굵기의 선, 같은 제목 모양이라 완성된 앱보다 와이어프레임처럼 보여요.
  • 표의 위계가 거꾸로예요. 핵심 목표와 영역 이름이 가장 흐리고, 우연히 달성한 칸이 가장 진해요. 그래서 무작위 체크무늬처럼 보여요.
  • 홈이 날짜부터 보여 줘요. 사용자가 이미 아는 정보예요. 목표와 오늘 할 일은 그 아래에 평범한 크기로 있어요.
  • 부품이 한 가족이 아니에요. 점선 '담기' 상자, 회색 체크박스, 겨자색 버튼, 설명 글자와 똑같이 생긴 누르는 글자.
  • 색이 한 계열뿐이에요. 따뜻한 종이, 갈색 먹, 갈색 선, 금색. '오늘'을 알리는 신호색이 없어요.
  • 여덟 영역 색 중 두 쌍은 구분이 어려워요. 한 쌍은 색각 이상이 있는 사람에게 같은 색으로 보여요.

어느 방향을 골라도 바뀌는 것

  • 표: 영역 이름 칸은 진한 색으로 고정하고, 달성한 칸은 옅게 표시해요. 범례와 '+' 표시는 없애요.
  • 홈: 표와 목표가 맨 위 주인공이 되고, 바로 아래에 오늘 할 일이 와요.
  • 탭 막대: 떠 있는 캡슐 모양이 되고, '담기'는 따로 떨어진 진한 버튼이 돼요.
  • 부품: 체크박스, 버튼, 줄을 하나의 규칙으로 통일해요. 기본 버튼은 먹색이에요.
  • 다크 모드: 색을 뒤집은 화면이 아니라 따뜻한 먹색으로 따로 설계해요.
  • 여덟 영역 색: 서로 잘 구분되게 다시 뽑아요.

화면별 비교

화면을 누르면 크게 볼 수 있어요. 네 화면 모두 같은 예시 데이터(목표 "단단한 한 해", 64칸 중 24칸 달성)예요.

조사의 한계

이 작업 환경에서는 열 수 있는 사이트가 Apple 개발자 문서와 GitHub 정도로 제한돼 있고, 웹 검색 한도도 중간에 소진됐어요. 그래서 다른 앱의 실제 화면은 직접 보지 못했어요. 그 부분은 Apple 문서, 검색 요약, 이미 알고 있는 지식에 기대고 있고, 메모마다 출처에서 읽은 것과 기억에 의존한 것을 구분해 뒀어요. 반면 우리 앱 진단은 화면 270장과 코드를 직접 보고 했고, 지적 하나하나를 증거와 다시 대조했어요.

다음 단계

  2. 방향을 골라 주시면 앱 전체에 적용해요. 표, 홈, 탭 막대, 부품, 색, 다크 모드 순서예요.
