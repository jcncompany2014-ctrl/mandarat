## Deviations from the reviewer's proposal

1. **F1 refusal on `same.to >= today`, not `=== today`.** On a device whose clock was set back, replacing the archive would shrink it to a shorter range, so that case is refused too. The YearClose `sameDay` notice then shows for that case as well. It is still a real "already closed" situation, not the stuck state.
2. **F3: once and extra ops collapse across days.** `planOps` keeps the last op per `(k, day)`. A once item or an extra is not tied to a day, so "checked on the widget yesterday, unchecked today" would have produced a `checkToday` from yesterday's op. Only the latest op per key (`lastOfKey`, `widgetOps.ts:89`) is applied for once and extra. Habits and counts stay per day.
3. **F3 count:** I used the cleaner `addCountOn` option, as the package asked, rather than the reviewer's fallback of `checkToday` on today.
4. **F6, ambiguous case:** suppose a cell is checked in the new chart on the closing day and then cleared that same day. Its key becomes `ti-xh<later tag>_ai`. If the old chart also had that cell on that day, the key has the same origin and is dropped too. The close time is not stored, so the tags cannot tell the two apart. This loses at most one check on one day, and in the rare direction (under-counting rather than double-counting).

## iCloud check (F1)

`syncLocal.ts:156-162` diffs archives per id into the `ar/<id>` path. A replaced archive is one `put` on the same register (LWW), so the later close wins on every device. Undoing such a close restores the earlier value with a new stamp, so it is not a tombstone. YearShelf, YearSheet, YearReview and print look archives up by id only. A replaced archive keeps its id, so they show the new range.
