## 2. Deviations from the plan, and why

1. **`expo install` runs offline.** `api.expo.dev` and `reactnative.directory` return 403 through the sandbox proxy.
   - Install and check used `EXPO_OFFLINE=1`, which resolves versions from `node_modules/expo/bundledNativeModules.json`.
   - That is the same SDK-56 table the online check uses, and it gives exactly the ranges the plan lists.
   - The online `npx expo install --check` cannot run here. The lead should re-run it on a networked machine.
2. **`fmt.daysLabel` takes `{ dows }`, not `{ days }`.** The plan's rule is "one parameter name, one type across all namespaces", and `days` is already the numeric parameter of `dueShort` and `dueLong`. The weekday list therefore gets its own name, `dows: readonly number[]`. `tests/i18n-catalog.test.js` feeds `[1, 3, 5]` for it.
3. **`fmt.time` is 24-hour in ja; ko and en take an optional `h24`.** The ja catalog ignores `h24` (the table shows only `21:00`). The catalog test passes a sample word for `h24`, since it is not in the numeric list; the output is still valid.
4. **`BANNED_JA` uses `/(?<!キャン)セル/` instead of `'セル'`.** The plain string matched キャンセル in `common.cancel`.
5. **`resolveLang` takes a 4th parameter, `override`, for `?lang=`.** The plan says `?lang=` wins without being saved but gave no signature for it. The new `langFromQuery(search)` parses it.
6. **Archive `reviews` window.** Review keys are Monday dates, so "filtered to `from..to`" keeps weeks whose Monday falls in `[from − 6 days, to]`. A week that straddles `from` belongs to the chart. `dayLog`, `dayMeta` and `closedDays` are filtered strictly to `from..to`.
7. **Stub types.** `contracts.ts` defines no interface for the widget bridge or Live Activity, so the default files export them: `WidgetBridge` and `WidgetEntry` from `src/widgets/bridge.ts`, `FocusLive` from `src/widgets/focusLive.ts`. The `.ios` files `import type` them; type-only imports are erased, so there is no platform-import problem. The stubs give their parameters explicit types, because `satisfies` alone keeps zero-arity lambdas.
8. **The native stubs are no-ops too.** `notifier.native.ts`, `crash.native.ts`, `bridge.ios.ts` and `focusLive.ios.ts` don't import their native packages yet; their owners fill them. `crash.native.ts` exports `SENTRY_DSN = ''`, per the Sentry fallback in the task.
9. **web-smoke additions.**
   - Extra flags `--out <dir>` (default `/tmp/web-smoke`) and `--dev` exporting to `dist-dev/`.
   - The known-warning list also covers three dev-bundle-only messages: the HMR socket, React DOM `collapsable`, and `transform-origin`.
   - Scenes are every `scripts/smoke/*.js` except `demoDoc.js`.
10. **`tests/i18n-hardcoded.test.js` scope.**
    - The prop rule also covers object-literal properties named `title`, `label`, `sub` or `body`.
    - Hex colour strings are ignored (`moods.ts` has `sub: '#6F6657'`).
    - Pending files are only held to the count ratchet.
11. **Plan typo.** The plan names `tests/i18n-catalog`'s fmt pin "`text.ts` formatters"; some of them live elsewhere. The test pins:
    - `duration` against `statsView.fmtMinutes`;
    - `weekNo` and `daysLeftYear` against `home.headerMeta`;
    - `daysLabel` against `routine.daysLabel`;
    - `ordinalCell` against `chartSpeech.ORDINAL`.
12. **Prebuild prints "Using expo@~56.0.23 instead of recommended expo@~57.0.7".** The `template.tgz` shipped inside `expo@56.0.23` is labelled `expo-template-bare-minimum@57.0.9`. This is upstream packaging. Prebuild uses it unchanged, `package.json` is untouched, and the generated project passes every check. I noted it rather than override the template.

## 4. Known gaps

- **Not done because it would publish:**
  - no Vercel preview deploy of the Wave 0 export;
  - no `v2-w1-base` tag (the branch isn't on `main`);
  - no pull request (per the task).

  The local web export and the Playwright smoke stand in for the deploy.
- **Online checks blocked.** The online `npx expo install --check` and the React Native Directory check are blocked by the proxy (Deviation 1).
- **Sentry `mandarat` project doesn't exist.** `SENTRY_DSN` is `''`, so `crash.init()` and every crash call do nothing.
  - The Sentry plugin is configured, and its iOS build phase runs. On EAS, `preview` sets `SENTRY_ALLOW_FAILURE=true`, but `production` does not.
  - So a production build fails at debug-symbol upload until both of these are done:
    1. the project exists;
    2. `SENTRY_AUTH_TOKEN` is set.

  This is intended by the plan (§1.2).
- **Native stubs are inert.** `notifier.native`, `bridge.ios`, `focusLive.ios` and `crash.native` do nothing until V1-A, V1-C, V2-B and V4-F fill them. The same goes for the hosts, the overlays, the `Year` screen (an empty page) and the Settings slots.
- **The language switch has no UI yet.**
  - `I18N_READY = false`; only `?lang=` and a stored pref (written by `chooseLang`, which no UI calls yet) change it.
  - Catalogs other than `common` and `fmt` are empty, so the app is Korean in every language.
- **The pending-list generator was not committed.** It was a one-off inline script. Re-deriving a list means grouping the §6.6/§6.7 file lists and calling `hangulCount` from `tests/i18nLint.js`.
