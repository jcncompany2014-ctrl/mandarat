# i18n — how strings work in 만다라트

The app ships in **한국어 (default and fallback)**, **日本語** and **English** (owner decision 4). Since V8-A every build follows the device language. This page is the short guide for anyone adding or changing copy.

## 1. Where strings live

```
src/i18n/ko/<ns>.ts     the source of truth (Korean, 해요체)
src/i18n/ja/<ns>.ts     satisfies Like<typeof ko>
src/i18n/en/<ns>.ts     satisfies Like<typeof ko>
src/i18n/<lang>/<name>.data.ts   word lists, regex sources, example lists (not messages)
src/i18n/glossary.ts    GLOSSARY rows, VOICE notes, BANNED_COPY / BANNED_JA / BANNED_EN
src/i18n/names.ts       LANG_NAMES, each in its own script
```

Every namespace has the same keys in all three languages (`tests/i18n-catalog.test.js`). A message is a string, or a function of one object parameter. A parameter name keeps one type everywhere: `n`, `count`, `total`, `done`, `days`, `mins`, `max`, `pct`, `h`, `m`, `y`, `y2`, `w` and `i` are numbers; `d`, `today`, `from` and `to` are Dates.

## 2. Adding a string

1. Add the key to `src/i18n/ko/<ns>.ts` first, then to `ja` and `en`. All three land in the same commit.
2. In a component, call `const m = useMsg();` once and read `m.<ns>.<key>`. In a pure module, call `msg().<ns>` **inside** the function (never at module scope), and take an optional `l?: Lang` for tests.
3. Libraries that return data return **codes**; the UI maps a code to a message.
4. Counts:
   - en: always `plural(n, one, many)` (`src/i18n/en/plural.ts`); a bare `${n} days` fails the lint.
   - ja: `tsu(n)` (`src/i18n/ja/counter.ts`) for つ / 個; other counters (回, 日, 週, マス, 件) follow the number with no space.
   - ko: attach particles with `josa()`.
5. Dates, times, durations, weekdays and day lists come from `fmt` (frozen; one implementation per language, no `Intl`). Do not format dates by hand.
6. Run `npm test`. These tests guard the rules:
   - `tests/i18n-hardcoded.test.js` (strict since V8-A): **no Hangul anywhere in `src`** outside `src/i18n/ko/**`, `names.ts` and `glossary.ts`, no JSX text with letters, and no literal passed to `accessibilityLabel`, `accessibilityHint`, `placeholder`, `title`, `label`, `sub`, `body`, `showToast`, `announce` or `Alert.alert`. Comments, regexes, `console.*` and the stored Mood/Mgmt/CellShape ids are not counted. There is no pending list any more.
   - `tests/copy.test.js`: the voice lint per language (below).
   - `tests/i18n-catalog.test.js`: equal key sets, every function called with sample params, no `undefined` / `NaN` / `[object`.
7. Check the screen in ja and en at 375 and 390 (`npm run web-smoke`, shots in `/tmp/web-smoke`). Fix overflow in the ja/en text or with the measuring helpers (`fitBox`, `labelLines`, `textWidth`), **never by shortening the Korean**.

## 3. Language resolution

1. Saved choice (`'system' | 'ko' | 'ja' | 'en'`, AsyncStorage `mandarat:lang:v1`, per device, not in backups or iCloud). On the web, `?lang=` overrides it without saving.
2. `'system'`: the first of ko / ja / en in the device locales, otherwise ko.
3. `public/index.html` sets `<html lang>` with the same order before the bundle loads, so the first paint uses the right fonts and line breaking.

`I18N_READY` is `true`. `resolveLang(pref, locales, auto)` keeps the `auto` parameter, so tests can still ask for the old ko-only behaviour with `auto = false`.

## 4. Voice

- **ko** — plain 해요체. 누르면 (not 탭하면), 했어요 (not 완료), 기록 (not 데이터), 칸 (not 셀).
- **ja** — です・ます, short. No 「！」, no emoji. 記録, never データ. UI names in 「」 (「今日」, 「できた」, 「設定」›「保存コピー」). Full-width 、。・ — no ASCII `·` in Japanese strings. Half-width digits, no space before a counter (7マス, 3回). Button and row labels are dictionary forms (書き出す, 始める); sentences are です・ます.
- **en** — sentence case, US spelling, no exclamation marks, no "Awesome / Great job / journey". "Today" is capitalised when it means the screen or list. `·` separates parts of a line.

Banned words (lint): ja セル, タスク, データ, ストリーク, 完了, マンダラチャート, ！, years such as 2026; en cell, task, data, complete(d), Mandal-Art, !, years.

## 5. Glossary

The table in `docs/v2/V8-A.md` §2 is the glossary as applied across all catalogs. Keep a Korean term on one translation; if a screen needs a shorter word, change it in every catalog (and in print) together.

## 6. What is not translated

- User content (goals, area names, actions, notes) — it stays as written. Korean text in a ja/en app keeps Korean word breaking (`breakLang`).
- Stored ids (`'일일 체크'`, `'연꽃'`, `'둥근'` …) — they are data; their labels come from `core`.
- Backups are language-neutral: a backup made in ja imports in ko.
- The App Store name, notification permission prompt and Home Screen name follow the iOS language through `locales/*.json` (app.json `locales`).
