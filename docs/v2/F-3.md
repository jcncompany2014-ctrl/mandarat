## Deviations from the reviewer's proposal

- **D-3.** I used the reviewer's `side = 515k` and also wrapped the page's lines to that width (`.cp>*`). On Letter, k is limited by the page height (k ≈ 0.934). There 515k = 481pt sits inside a 530pt content box, so the chart alone would still have been inset by 24pt.
- **A-4.**
  - The spoken chart line is a new `progress` key, not `fill(L.left, …)`. "n개 남았어요" does not say how many were done.
  - The lock-screen rectangular ticks used the same `n/m` label, so they use `progress` too.
  - Snapshots written by an older app build have neither key, so both labels fall back: rows read the bare text and the chart keeps the old `n/m 오늘`. A label is never empty.
- **D-11.** `s <= 32` hides the caption on systemSmall (32) and systemMedium (30). Only systemLarge (36) shows "오늘", as proposed.
- **D-12, `04-stats`.**
  - The wear map still has no `testID`. Instead of the fixed distance, the scene finds the row whose text is exactly the app's catalog string `msg(lang).stats.secAreas`, inside the scroll box of `TID.statsYear`. The flow is the same in every language. This is the only text lookup in `scenes.js`, and `tests/storeShots.test.js` pins that.
  - `TID.statsWear` stays the preferred path and `statsLift` the last fallback.
- **D-12, `05-ritual`.** I took the reviewer's "crop to the column with paper margins" option. The app has no way to open the ritual on the spread's left page, and that would be an app change outside this package. 704pt is the app's own `column` layout (600 ≤ w < 960), as in a Split View or Stage Manager window.

## Device-test additions
For the lead to fold into `docs/v2/device-tests.md` (owned by F-2, not edited here):

- **Live Activity, accepted system exception.** The banner and the expanded island use the linear `ProgressView` (`progressViewStyle('linear')`), which draws iOS's rounded capsule track. It is the only way to fill a bar from `timerInterval` without the app running, so it stays. On device, check:
  - it fills ink-on-paper over the 25 minutes;
  - it freezes on pause;
  - it is full when done.
- **Live Activity, minimal.** With two Live Activities running, the minimal view shows only the area-colour square (no clock). A tap opens the expanded view with the countdown. VoiceOver reads the area name.
- **Widget rows, accepted exception to rule 7.** Medium/large rows are full-width buttons, `minHeight` 22pt, below the 44pt rule. This is the system pattern for interactive widgets, which iOS hit-tests by row. On device, check that every row toggles with one tap and that neighbours are not hit.
- **Widget VoiceOver.** A row reads "{text}, 아직 안 했어요" or "{text} — 했어요", and flips after a tap. The chart reads "오늘 10개 중 3개 했어요" (ja and en likewise), with no slash.
- **Widget centre caption.** "오늘" shows only on systemLarge, at 9pt medium. Small and medium show just `n/m`.
